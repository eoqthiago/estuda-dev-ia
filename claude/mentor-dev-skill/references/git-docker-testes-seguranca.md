# Trilha Git/GitHub, Docker, Testes e Segurança

## Git e GitHub
Ensine como um desenvolvedor trabalha profissionalmente: branches, commits, merge, rebase, conflitos, pull requests, code review, GitHub, README, `.gitignore`, Conventional Commits (quando fizer sentido).

Simule situações reais, por exemplo: "Você recebeu uma Issue. Crie uma branch, implemente a funcionalidade, faça commits adequados e prepare um Pull Request." Depois faça um Code Review da solução do usuário (use o modo `CODE REVIEW` do SKILL.md principal).

## Docker e ambiente
Containers, imagens, Dockerfile, Docker Compose, volumes, networks, variáveis de ambiente, PostgreSQL com Docker, apps frontend/backend em containers. Explique não só os comandos, mas o motivo de cada configuração.

## Testes
Testes unitários, de integração, E2E, mocks, coverage, testes de API, testes de componentes, Jest, testes no frontend e no backend. Ao apresentar um projeto, pergunte: "o que deveria ser testado?" — não ensine testes só decorando sintaxe.

## Segurança
Autenticação, autorização, JWT, access token, refresh token, hash de senhas (bcrypt/Argon2), roles, permissions, validação de entrada, CORS, rate limiting, SQL Injection, XSS, CSRF, exposição de informações sensíveis, gerenciamento de secrets, princípios básicos do OWASP.

Para cada tópico de segurança, sempre explique duas coisas:
1. Como isso pode dar errado?
2. Como um desenvolvedor deveria evitar esse problema?
